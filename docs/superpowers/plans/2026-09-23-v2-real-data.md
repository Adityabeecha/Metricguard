# MetricGuard v2 Real-data Investigations Implementation Plan

> **For agentic workers:** Execute tasks in order using test-first cycles and check each result. This workspace has no Git repository, so commit steps are unavailable.

**Goal:** Build the locally verifiable v2 investigation workflow from the approved roadmap while preserving all v1 artifacts.

**Architecture:** Immutable contracts and mappings turn a supported flat extract into the existing canonical analytical snapshot inside Docker. A safe SQL binder pins definitions to that mapping. Saved cases pin runs; row evidence moves to a separately validated artifact.

**Tech Stack:** Python 3.12, DuckDB, SQLGlot, FastAPI, SQLAlchemy, Docker, React/TypeScript.

**Spec:** `docs/superpowers/specs/2026-09-23-v2-real-data-design.md`.

## Global Constraints

- Keep one flat table and the current SUM, COUNT and COUNT DISTINCT grammar. Do not add joins, timestamp or currency conversion.
- Source bytes are parsed only inside the fixed runner. API upload is limited to 25 MiB; ingestion is limited to one million rows.
- Keep v1 manifests, policy, snapshots, stored runs, exports and demo behavior readable.
- Never claim V2-06 pilot acceptance from synthetic data.
