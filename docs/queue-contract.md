# Supervisor/store contract

`services.api.store.Store(database_url)` provides `claim(worker_id, lease_seconds=90) -> dict|None`, `heartbeat(run_id,worker_id,attempt,lease_seconds=90)->bool`, `finish(run_id,worker_id,attempt,result=None,error=None)->bool`, `get_run(id)->dict`, `cancel(id)->dict`, `snapshot(id)->dict`, `version(id)->dict`.
Claim returns Run (docs/contracts) plus `attempt`, `lease_owner`, `lease_expires_at`, `cancel_requested`. Only queued or expired running jobs claimable, cancellation blocks claims. Atomic conditional updates. finish accepts only current nonexpired lease and current attempt; result successful if result explanation complete else partial; errors failed. cancel queued -> canceled immediately; running sets cancel_requested; runner killed by supervisor and terminal canceled through finish. Result cannot overwrite terminal state.
Snapshot internal record includes `artifact_path` (absolute .duckdb path), `manifest` full ingestion manifest. Version includes raw_sql/ir. Worker gets `METRICGUARD_DATABASE_URL` default sqlite:///data/metricguard.db and `METRICGUARD_DATA_DIR` default ./data.
Supervisor must not launch demo mode jobs (API resolves those against saved evidence); only execution_mode `isolated` queued. Fixed image `metricguard-runner:1.0` or pinned administrator env; job input: snapshot hash, baseline IR, target IR, context. Container input/snapshot readonly, output writable bounded temporary; network none, read-only root, non-root, capabilities none, no-new-privileges, 1GiB/1cpu/pids limit. Runner core compare input generated by trusted code. Job wall timeout 60 sec. Honor cancel and heartbeat. Validate output JSON structure and numeric reconciliation before finish.
Store.record_definition(name,source_label,owner_label,raw_sql,time_column,definition_id=None)->Definition; Store.record_snapshot(name,manifest,artifact_path)->Snapshot; Store.queue(request,idempotency_key,execution_mode)->Run. Store.bootstrap()->dict.

Browser ingestion uses `queue_import(source_path,source_hash,name,metadata)`, `claim_import(worker_id,lease_seconds)`, `heartbeat_import(id,worker_id,attempt,lease_seconds)` and `finish_import(id,worker_id,attempt,manifest,artifact_path,error)`. The API writes only to a generated path under `data/uploads`; it does not parse CSV or launch containers. Equal source bytes and business metadata reuse a pending import or validated snapshot. The supervisor verifies the staged source hash, runs `isolated_ingest` in the fixed container, and checks database, source and manifest hashes, schema and declared metadata before `finish_import` atomically publishes a snapshot. Known core CSV validation errors return bounded code/message data through `error.json`; crashes remain generic. A failed import has no snapshot ID. Expired leases can be reclaimed; stale attempts cannot finalize. Staged CSV is removed after terminal completion. The public API omits `source_path` and artifact paths.
