# MetricGuard local implementation interfaces

The original v1 interfaces below remain supported. V2 extends the same `/api/v1` base path for compatibility; it does not rename the original planning pack or reinterpret stored v1 records. See [v2 release evidence](v2-release-evidence.md) for verification status.

Base `/api/v1`; all JSON amounts are decimal strings. Errors `{error: {code, message}}`.

GET `/bootstrap` returns `{project:{id,name}, mode:"demo"|"isolated", runner_available:boolean, definitions:Definition[], snapshots:Snapshot[], imports:SnapshotImport[], candidates:Candidate[], runs:Run[], baselines:[], dependencies:[], reviews:[]}`. The candidate list shows the top 50 heuristic matches.

Definition: `{id, name, source_label, owner_label, versions:Version[]}` (versions ascending).
Version: `{id, definition_id, version_number, raw_sql, time_column, support_state:"executable"|"needs_context"|"unsupported", support_reason, raw_hash, ir_hash, ir:object|null, observed_at, source_changed_at:date|null, effective_from:date|null, change_kind:"initial"|"metadata_only"|"cosmetic"|"structural"|"unknown"}`. Source/effective dates are optional analyst declarations; observation time is recorded by the workspace.
Snapshot: `{id,name,row_count,manifest_hash,source_hash,currency,timezone,scope,grain,cutoff_at,schema,status,created_at}`.
Run: `{id,baseline_version_id,target_version_id,snapshot_id,context,relationship,purpose:"comparison"|"definition_replay",state,created_at,result:Result|null,error:object|null,execution_mode}`.
SnapshotImport: `{id,name,source_hash,metadata,state:"queued"|"running"|"validated"|"failed",attempt,created_at,completed_at,snapshot_id,error}`. The staged source path is never returned.
Candidate: `{left_definition_id,right_definition_id,left_version_id,right_version_id,score,reasons,cautions,review_status,review_id}`. Score is heuristic points, not probability or approval.

POST `/definitions` body `{name,source_label,owner_label,raw_sql,time_column,source_changed_at?,effective_from?}` returns Definition. POST `/definitions/{id}/versions` body same (name/source optional) returns Version. GET `/definitions/{id}/history` returns Definition.
POST `/snapshots` multipart fields `file`, `name`, `currency`, `timezone`, `scope`, `cutoff_at` accepts a `.csv` or `.parquet` file with the exact ordered nine-column orders schema and declared types. It reuses a validated Snapshot for identical bytes and business metadata, or returns a queued SnapshotImport (202) in isolated mode. New bytes in demo mode return `ISOLATION_REQUIRED`. GET `/snapshot-imports/{id}` returns current status; only a validated import produces a Snapshot. CSV applies its declared blank-token NULL policy; Parquet preserves native NULLs and requires matching DuckDB types, including `DECIMAL(18,2)` for amounts and `DATE` for dates. Both enforce the same 25 MiB, one-million-row, unique-order-ID, INR and Asia/Kolkata limits.
GET `/candidates` returns `{method:"deterministic_heuristic_v1",items:Candidate[]}` for current executable pairs sharing aggregate family and source table. A latest recorded pair review determines `review_status`.
POST `/comparisons/validate` and POST `/comparisons` accept `{baseline_version_id,target_version_id,snapshot_id,context:{start,end_exclusive,timezone,currency,unit,grain,scope},relationship:"expected_agreement"|"intentional_variant"|"candidate"}`. Run creation requires `Idempotency-Key` header. Returns Run (202). GET `/comparisons/{id}` returns Run. POST `/comparisons/{id}/cancel` returns Run. GET `/comparisons/{id}/evidence?offset=0&limit=100` returns `{items,total}`.
POST `/definitions/{id}/replays` takes the same body and idempotency header, requires two ordered versions of that definition, and returns a run with `purpose:"definition_replay"`. It applies normal comparison context and fixed-snapshot validation.
GET `/comparisons/{id}/export?format=json|html` downloads full report. GET `/snapshots/template` downloads the golden CSV.
POST `/pair-reviews` body `{left_definition_id,right_definition_id,relation,reason,actor_label}`.
POST `/baselines` body `{version_id,scope,reason,actor_label,effective_from}`.
POST `/dependencies` body `{definition_id,label,kind}`.

Result: `{baseline_value,target_value,delta_target_minus_baseline,absolute_gap,relative_change_percent_display,residual,currency,numeric_tolerance,method,definition_status,value_status,explanation_status,steps:[{position,rule,previous_value,next_value,contribution}],evidence:[{order_id,baseline_included,target_included,baseline_contribution,target_contribution,delta,baseline_null_term,target_null_term,membership}],definition_differences:[{rule,baseline,target,changed}],provenance:{...},limitations:string[]}`. `null` endpoints/gap are unavailable, not zero. Status values follow planning chapter 2.

Core API: `from packages.metricguard_core import parse_definition, ingest_csv, ingest_parquet, compare, CoreError`. `parse_definition(sql, time_column=None)` returns serializable IR with fingerprint included as `ir_hash`; original raw text is stored outside IR. `ingest_csv(source:Path,destination:Path,metadata:dict|None=None)` and `ingest_parquet(source:Path,destination:Path,metadata:dict|None=None)` write an immutable DuckDB file and return a manifest including `database_hash`, `source_hash`, `manifest_hash`, `row_count`, `schema`, and format-specific `ingestion_version`. `compare(database:Path, baseline:dict, target:dict, context:dict)` revalidates IR and returns above Result. Context dates must agree with literal periods if present. Core `CoreError` has `.code` and `.message`.

## V2 local mapped investigations

`POST /dataset-contracts` approves a version-2 contract. Its required JSON fields are `version:2`, `name`, `currency`, `timezone`, `scope`, `grain`, `cutoff_at` (`YYYY-MM-DD`), `null_policy`, `row_key:"order_id"`, `entity_key:"customer_id"`, `decimal_scale:2` and `schema`. `schema` must declare exactly these canonical analytical roles and DuckDB types: `order_id` and `customer_id` as `VARCHAR`; `order_date` and `payment_date` as `DATE`; `status`, `payment_status` and `currency` as `VARCHAR`; `order_amount` and `refund_amount` as `DECIMAL(18,2)`. The three NULL policies are `blank_nullable` and `literal_NULL` for CSV, or `native_null` for Parquet. Response adds immutable `id`, `version_number`, `contract_hash` and `created_at`. `GET /dataset-contracts/{id}` fetches it. Reapproving identical content returns the prior identity; a changed policy receives a new hash and record.

`POST /column-mappings` takes `{contract_id, columns:{canonical_role:source_column}}`, one distinct source column for each of the nine roles. Response adds `id`, `version_number`, `contract_hash`, `mapping_hash` and `created_at`; `GET /column-mappings/{id}` fetches it. Source files may have extra columns. Approval does not infer transformations or make unknown columns executable.

`POST /dataset-previews` accepts a `.csv` or `.parquet` multipart `file` (1 byte–25 MiB) in isolated mode, returns a queued preview record, and runs source parsing inside the fixed container. Poll `GET /dataset-previews/{id}` until `state` is `previewed` or `failed`. A successful preview includes source hash, headers, declared and observed types, and at most five bounded sample rows; it is for mapping review, not a validated snapshot. Preview jobs are excluded from the normal bootstrap `imports` list.

`POST /mapped-snapshots` takes multipart `file`, `mapping_id` and optional `name` (1–160 characters) in isolated mode. Poll its returned import through `GET /snapshot-imports/{id}`. The runner validates the declared NULL policy, exact mapped Parquet types or CSV values, one-to-one mapping, unique row keys and consistent currency, then publishes the canonical immutable snapshot. Input size is at most 25 MiB and row count at most one million. Its manifest and public snapshot include `source_hash`, `contract_hash` and `mapping_hash`. The v1 `POST /snapshots` route remains the exact-schema import.

`POST /definitions` and `POST /definitions/{id}/versions` accept an optional `mapping_id`. A mapped definition may use approved source column names in the existing restricted DuckDB SQL grammar. Its version stores `raw_sql`, `bound_sql`, `source_time_column`, canonical `time_column`, `contract_hash` and `mapping_hash`. An unknown source identifier fails; changing a mapping requires a new definition identity. The original v1 definition shape stays valid without `mapping_id`.

For a mapped `POST /comparisons/validate` or `POST /comparisons`, the `context` includes the matching `contract_hash` and `mapping_hash` in addition to the v1 period, currency, timezone, unit, grain and scope. Both definition versions and the selected snapshot must carry those exact identities and share an aggregate family. The result provenance records the frozen input identities. No uploaded SQL runs inside the API process.

`POST /investigations` accepts `{title, run_id, decision, actor_label, snapshot_id?}` after a successful or partial run. The saved record pins the run, snapshot, baseline and target versions, context and relationship. `GET /investigations` lists local cases; `GET /investigations/{id}` resolves the pinned objects and reports `replay_available`; `POST /investigations/{id}/replays` with `Idempotency-Key` queues a same-input replay when the snapshot artifact still exists. Actor and decision labels are local self-declarations, not authenticated approvals.

An isolated v2 run stores a compact `result` with `evidence:[]` and `evidence_artifact:{sha256,row_count,byte_count,delta_sum}`. The separate JSONL artifact is verified by the supervisor before publication. `GET /comparisons/{id}/evidence?offset=0&limit=100` verifies the artifact and returns `{items,total}` with `limit` from 1 to 100; historical inline v1 evidence still pages through this route. JSON and HTML `/comparisons/{id}/export` include a bounded first page and `evidence_coverage:{total_rows,included_rows,omitted_rows,detail}` for artifact-backed results. A 25 MiB export cap remains. The API returns `EVIDENCE_INTEGRITY` if saved artifact bytes fail validation.
